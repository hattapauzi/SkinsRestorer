# Forge 1.12.2 companion mod — design

Date: 2026-09-21  
Status: draft for this fork (not an upstream issue)  
Audience: implementers working on `hattapauzi/SkinsRestorer`

## Problem

Official SkinsRestorer does not ship a **native Minecraft Forge 1.12.2** mod. The Bukkit jar already covers 1.8–latest (Java 8 bytecode via JVMDowngrader). The official Fabric/NeoForge mod targets **Minecraft 26.3**. Dedicated Forge 1.12.2 (Java 8) has no first-party adapter.

Hybrid 1.12.2 loaders (Mohist, Magma, CatServer) already run the Bukkit jar. This work is only for **pure Forge**.

## Decision

**Standalone companion inside this fork, not wired into the parent Gradle build.**

**Dependency/shade model (one pass):** compile against the **unshaded** `skinsrestorer-shared` / `skinsrestorer-api` / `skinsrestorer-build-data` / `skinsrestorer-scissors` jars plus the same Maven coordinates shared uses (`gradle/libs.versions.toml`). Do **not** consume `*-all.jar` / platform-shadowed jars. Companion `shadowJar` relocates the same packages as parent `sr.shadow-logic` **plus** `net.kyori` → `net.skinsrestorer.shadow.kyori`. Lombok is compile-only (not shaded).

**Release jar pipeline:** `compileJava` (MCP names) → `shadowJar` (still MCP) → RFG **`reobfJar`** (SRG method/field names) → JVMDowngrader to Java 8 → downgrader `ShadeJar`. The file you put in `mods/` is the **reobfuscated** downgraded jar. Gate: `runObfServer` must reach a dedicated-server “Done” without `NoSuchMethodError`.

| Option | Verdict |
|---|---|
| In-tree `include()` in `settings.gradle.kts` | No. Parent is Gradle 9.7.1 + configuration cache + Architectury Loom. Forge 1.12 needs RetroFuturaGradle. |
| Hard-fork of every platform | No. Do not diverge Bukkit/NeoForge/Velocity. |
| Nested independent project `forge-1.12/` | Yes. Own settings/wrapper. `cd forge-1.12 && ./gradlew build`. Shade Java 8–downgraded shared+api. |

If upstream later wants an official in-tree module: keep these adapter classes; switch only the build (compile-only deobfuscated Maven + existing JVMDowngrader). Same contracts.

## Seam (one)

The existing **server-platform contract**. Do not add new shared interfaces. Do not reuse `mod/common` (wrong Minecraft).

Bootstrap calls `SRBootstrapper.startPlugin` with:

- `SRForge112Adapter` implementing `SRServerAdapter`
- `SRServerPlugin` (shared)
- `SRForge112Init` implementing `SRServerPlatformInit`
- `SkinApplierAccess<EntityPlayerMP>`
- login wrapped as `SRLoginProfileEvent` → `LoginProfileListenerAdapter`

Skin refresh protocol matches Bukkit 1.12 (`LegacySpigotSkinRefresher`): mutate `GameProfile` `textures`, then tab-list REMOVE/ADD + respawn + position for self, hide/show for others.

## Layout

```
/                          ← parent SkinsRestorer Gradle 9 build (unchanged except Platform.FORGE)
forge-1.12/                ← independent RetroFuturaGradle project (never include()'d)
  settings.gradle
  build.gradle
  src/main/java/net/skinsrestorer/forge112/
  src/test/java/...
docs/superpowers/specs/    ← this file
docs/superpowers/plans/    ← implementation plans
```

Tiny parent patch: add `FORGE("Forge", PlatformType.SERVER)` to `Platform`. Required so `getPlatform()` is honest. Safe to upstream independently.

## Runtime

- Minecraft **1.12.2** + Forge **14.23.5.2847**
- Dedicated server. `acceptableRemoteVersions = "*"` so clients do not need the mod.
- Java 8 at runtime. Companion compiles with Java 25 + Jabel (Cleanroom ForgeDevEnv style) or equivalent; final shaded jar is bytecode-downgraded to 8 (same `jvmdowngrader` the Bukkit jar uses).
- Abort startup if `org.bukkit.Bukkit` is on the classpath (hybrid → use official plugin).

## What the companion implements vs reuses

Reused (shaded): storage, Mojang/MineSkin, locales, Cloud-annotated commands, GUI page model, plugin-message codecs, API.

Implemented here:

| Piece | 1.12.2 mechanism |
|---|---|
| Entry | `@Mod` + `FMLServerAboutToStartEvent` |
| Scheduler | `MinecraftServer.addScheduledTask` + daemon executor |
| Login | `PlayerEvent.PlayerLoggedInEvent`, same contract as Bukkit `EventWrapper`: `runAsync` = adapter executor (never inline on the server thread); `setResultProperty` = `SkinApplierForge112.applySkin`. Storage/Mojang stay off-thread. |
| Apply | Mutable authlib 1.5 `GameProfile.getProperties()` on the **server thread** inside `applySkinSync` |
| Refresh | Tab-list REMOVE/ADD to the player list (global). Entity destroy/spawn **only** to `EntityTrackerEntry.trackingPlayers` in the same world. Self: respawn + position. |
| Commands | Cloud `CommandManager` + Forge `ICommand` bridge (no Brigadier) |
| Chat | Adventure JSON → legacy `§` `TextComponentString` |
| GUI | 1.12 chest `IInventory` + skull `SkullOwner` NBT |
| Plugin channel | Register `NetworkRegistry.INSTANCE.newEventDrivenChannel(SRHelpers.MESSAGE_CHANNEL)`. Receive: `FMLNetworkEvent.ServerCustomPacketEvent` (copy `ByteBuf` into a new `byte[]`, never retain the buffer). Send: vanilla `SPacketCustomPayload` (proxy-compatible). Wrong channel / decode errors: log and return. |
| Permissions | Ops = all nodes true; non-ops = default group via `Permission.isInDefaultGroup`; optional permission-mod later |
| Metrics / sounds | Metrics `null` (shared already skips). Sounds: 1.12 `SoundEvent` map or no-op. |

## Non-goals

- Other Forge versions
- Client-only cosmetics
- ForgeGradle 2.3 in the parent build
- Reimplementing commands, storage, or Mojang clients
- Official Modrinth “Forge” on the main artifact until SRTeam agrees
- Guaranteeing Geyser / every 1.12 permission mod
- Companion-specific update-checker URL in v1 (shared still points at official SkinsRestorer releases; install jars from this fork’s GitHub Releases by hand)
- ViaVersion workarounds beyond what shared already no-ops when Via is absent

## Test seam

External behaviour only:

1. `GameProfile` + `SkinProperty` → `textures` replaced, other properties kept.
2. Login wrapper: `runAsync` is delegated (does not run on the caller thread unless the test executor does); `setResultProperty` invokes the apply sink, not a second immediate read.
3. Shared Mojang/storage tests stay in the parent `test/` module — do not copy.
4. Packet class names are not unit-tested. In-game (`runObfServer`): self sees skin, others **in tracking range in the same dimension** see the entity update; tab head updates for the player list.
5. Plugin-message receive: copy payload bytes, decode a fixture encoded with `SRServerPluginMessage.CODEC`, ignore wrong channel, swallow malformed payloads.
